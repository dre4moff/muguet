# Fork r5 validation — 2026-10-11

The owner's r4 screenshots show 35.6–36.9 FPS, 27.1–28.1 ms/frame and 26.5–27.5 native renderer CPU ms/frame, with 3,361–3,370 draws and near-zero ring/fence/drawable waits. This identifies a serial CPU command-processing limit in those windows. The exact cause of the initial 60-to-30/40 transition is not established by screenshots taken only afterward. Memory headroom remains available and reported thermal state is Normal.

- Removes repeated immutable binding-description copies, string resource lookup keys, per-draw pass-format copies and vertex-stride allocations. Pipeline-key values, render inputs, shader/texture/geometry behavior and required synchronization remain unchanged.
- Adds an eight-entry pool for empty command trackers, recycled only when the original command-buffer lifecycle permits release. Clears ownership, barriers/complex texture state and queries before reuse. Deduplicates owning stateless references by retained Arc identity; every distinct binding remains subject to destroyed-resource validation.
- Seven app Rust tests passed with the owner's ZIP opened read-only, including 1,113 vertex shader validations, existing uniform byte equivalence and controller tests, asynchronous GPU query correctness, and 32 exact pixel/readback results spanning in-flight resource lifetimes and tracker reuse. An overwritten/destroyed binding still fails validation as required. Two synthetic benchmarks are explicitly ignored by default; they are not iPhone FPS tests.
- Five-repeat native tracking comparisons, with agent compilers idle, measured about 13.7–14.5% less recording/encoding/queue wall time at 8,192–65,536 live buffers. At 65,536: 2.667 to 2.280 ms on the Mac synthetic workload; this is not a game FPS result.
- All 67 vendored wgpu-core unit tests passed, including interleaved ownership deduplication/clear/reuse reference-count checks and sparse membership iteration across word boundaries, growth and truncation. Native Swift import-deletion protection tests passed.
- HUD separately measures encoder.finish translation and queue.submit wall time, adds pass/submit/pending-draw counts, removes overlapping GPU interval sums from the displayed frame budget, and defaults GPU timestamp profiling off independently of the CPU/memory HUD. Ordinary HUD uses no GPU query/readback resources.
- Host/iOS builds, unsigned package integrity, embedded-code digest, license and delivery checks are recorded in the local release evidence. Only these completed checks establish artifact readiness; device gameplay and FPS improvement remain untested for r5.
- Memory/heap policy, working controller, compatible game ZIP, ZIP cleanup and manual iLoader signing/install workflow remain intact. MetalFX remains absent. The public GPL fork/release contains source and documentation only, with original/vendored licenses retained and no game-bearing IPA, Wasm or assets uploaded.

Test procedure for the owner: keep GPU timing off, enable the ordinary Performance HUD, use the same scene and 60 FPS cap, capture around 5 seconds and after 20–30 seconds. Compare renderer CPU, Metal encode, queue, draws, pending draws and passes/submits; repeat with the HUD fully off for normal gameplay. Host synthetic timings do not predict the device gain or guarantee 60 FPS.
